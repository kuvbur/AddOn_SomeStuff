# Перевод вики RU → EN

`translate_ru2eng.py` — точка входа; `wiki_translation.py` — обработка Markdown,
кэш и HTTP-клиент. Python 3.10+.

## Установка

```bash
python -m pip install -r wiki/tools/requirements.txt
```

Используйте тот же Python для установки зависимостей, тестов и запуска.

## Сначала проверить без перевода

```bash
python wiki/tools/translate_ru2eng.py --dry-run
python wiki/tools/translate_ru2eng.py --check
python wiki/tools/translate_ru2eng.py --dry-run --file Home.md --file Finishing-ru.md
```

Эти режимы не читают API-ключи или `.env`, не вызывают API и не записывают файлы.
Проверяется возможность безопасно разобрать выбранный Markdown; выводится
`CURRENT` или `STALE`. `--check` возвращает 1 при устаревших/непроверенных EN,
0 при актуальных; ошибка входных данных даёт 2. `--dry-run` возвращает 0,
если проверка входных данных успешна, даже когда перевод ещё нужен.

Пути по умолчанию вычисляются от скрипта, а не от текущей папки. Для запуска
из другого каталога передайте абсолютный путь к `translate_ru2eng.py`.
Явно заданные относительные пути считаются от текущего каталога.

## Реальный перевод — платный API

Задайте `OPENROUTER_API_KEY` в окружении или в корневом `.env` репозитория.
Прежнее имя `DEEPSEEK_API_KEY` поддерживается как запасной вариант.
Если заданы оба, используется `OPENROUTER_API_KEY`.

```bash
python wiki/tools/translate_ru2eng.py --file Home.md
```

Без `--file` обрабатываются все `*.md` непосредственно в `wiki/ru/`.
`Page-ru.md` превращается в `Page-en.md`, `Home.md` — в `Home-en.md`,
`_Sidebar.md` сохраняет имя. EN-файлы считаются генерируемыми:
**ручные изменения EN при обычном запуске могут быть заменены переводом из кэша**.
RU-файлы не перезаписываются. Удалённые из RU разделы удаляются и из
пересобранного EN; EN-файлы целиком не удаляются при удалении RU-страницы.

Дополнительные параметры:

- `--source-dir`, `--target-dir`, `--image-dir`, `--cache` — альтернативные пути;
- `--force` — не использовать готовые переводы; повторный запуск может стоить денег;
- `--model` — модель (по умолчанию прежняя `deepseek/deepseek-v3.2`);
- `--base-url` — HTTPS endpoint; ключ отправляется именно этому адресу;
- `--timeout` — таймаут HTTP, по умолчанию 120 секунд;
- `--retries` — число повторов временных сетевых/HTTP-ошибок, по умолчанию 2, максимум 5;
- `--max-chars` — лимит исходного Markdown-блока, по умолчанию 16000 символов.

Ограничение символов — не точный токеновый бюджет модели. Неделимый блок
(например, большая таблица) не режется посередине: если превышен лимит,
скрипт останавливается до запросов; увеличьте `--max-chars` осознанно.
Оборванный ответ, повреждённые плейсхолдеры или изменённая структура не сохраняются.
Повтор после сетевого таймаута потенциально означает повторный платный запрос.

## Защита и кэш

CommonMark-парсер с таблицами определяет заголовки, блоки кода и HTML.
Код, технические идентификаторы, email, адреса ссылок, отступы и переводы строк
защищаются плейсхолдерами. Проверяются их порядок/целостность, защищённое
содержимое и структура Markdown. HTML-блоки сохраняются целиком, включая
содержащийся в них русский текст. Это намеренное ограничение.

У shortcut/collapsed reference-ссылок подпись одновременно является
идентификатором: она сохраняется без перевода, чтобы не порвать ссылку на
определение в другом разделе. У явной формы `[подпись][id]` подпись переводится,
а `id` остаётся исходным. Проверяется структура всего собранного документа.

Подписи ссылок переводятся; адреса wiki-страниц этого репозитория переключаются
на `-en`, адрес картинки меняется только при наличии EN-файла и с его реальным
регистром. URL внутри кода не меняются. Доступность URL по сети и наличие всех
целевых английских wiki-страниц не проверяются.

Новый кэш — `wiki/tools/translation_cache.v2.json`. Старый
`translation_hashes.json` не меняется и не используется: его хэши не доказывают,
что перевод когда-либо успешно завершился. **Первый реальный запуск создаёт
новый кэш и может перевести все выбранные страницы заново.**

Кэш содержит проверенные переводы блоков, точные хэши и версию настроек.
Обычный запуск и `--check` используют одну проверку схемы и контрольных сумм
переводов. Повреждённый кэш даёт ошибку, а не ложный статус `CURRENT`.
Перестановка/удаление разделов не требует повторных запросов для неизменённых
блоков. Смена модели/промпта инвалидирует переводы. EN сначала записывается
через временный файл и замену, затем сохраняется кэш. Это не единая транзакция
двух файлов: сбой записи кэша оставляет готовый EN и приводит к безопасному
повтору работы. Атомарность действует на отдельную страницу, а не на весь набор.
Не запускайте несколько процессов с одним кэшем одновременно.

Перевод сохраняет LF/CRLF исходника, конечный newline и пробелы; выход — UTF-8
без BOM. Правильность терминологии и полноту смысла всё равно нужно проверить
человеку: структурные проверки не являются лингвистической приёмкой.

## Офлайн-тесты

```bash
python -m unittest discover -s wiki/tools -p "test_translate_ru2eng.py" -v
```

Сеть заменена контролируемым HTTP-клиентом; файловые операции выполняются
на временных fixtures. Настоящие страницы вики тестами не переводятся.
