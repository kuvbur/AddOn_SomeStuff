# i18n каталог BrowserPalette

`Interface_ru.html` — единственный редактируемый исходник логики и вёрстки.
`Interface_en.html` **генерируется** и руками не правится: любая правка в нём
пропадёт при следующем `generate`.

## Файлы

| Файл | Роль |
|---|---|
| `inventory.md` | Карта переводимых строк: что переводится, что нет, и почему |
| `glossary.md` | Термины с указанием источника и уровня доказательности |
| `en.json` | Переводы RU → EN |

## Формат `en.json`

```json
{ "key": "nav.spec", "source": "Спецификация", "context": "Надпись вертикальной вкладки",
  "translation": "Specification", "reviewed": true }
```

- `source` обязан **точно** совпадать с `text` в `I18N_CATALOG` русского файла.
  Изменился русский текст — запись станет `stale` и потребует пересмотра.
- `reviewed: true` ставится только после проверки смысла; автоматического
  подтверждения нет.
- Плейсхолдеры `{имя}` должны совпадать с русским оригиналом — сверяется
  автоматически (`placeholderMismatch`).

## Обычный цикл

1. Изменили строку в `Interface_ru.html`.
2. `npm run i18n:status` — покажет `missing` (новые) и `stale` (изменился source).
3. Перевели **только** их в `en.json`.
4. `npm run i18n:generate`.
5. `powershell -File Tools\test_html.ps1`.

Если менялась только логика или вёрстка, а строки не трогались — достаточно
`npm run i18n:generate` (каталог не изменился, файл пересобирается).

## Что переводится, а что нет

**Переводится** интерфейс: подписи, подсказки, состояния, названия вкладок,
заголовки блоков, легенда подсветки синтаксиса.

**Не переводится:**

| Что | Почему |
|---|---|
| Имена свойств, классификаций, групп | пользовательские данные проекта |
| Метки пресетов от `GetFilterPresets` | приходят из C++, хранятся в настройках |
| Значения DSL: `NULL`, `SPACE`, `без суффикса` | попадают в `Renum_flag{…}` — изменится создаваемый Renum |
| Мок-данные: `STR-001 Стена несущая`, `Sync_GUID+…` | имитация ответа моста |
| Маркеры regexp: `/пусто|empty/`, `/шаблон/` | часть регулярного выражения |
| Команды и ключевые слова подсветки | это синтаксис DSL |

## Ловушка «подпись = значение»

Некоторые строки работают и как видимая подпись, и как признак состояния.
`Закреплённые` — имя синтетической группы, и оно же сравнивается при рендере.
Такие строки проверить: `t("key")` должен стоять в **обоих** местах, а
сравниваться может только с тем же вызовом.

## Термины SomeStuff

`Specification` / `Renum` / `Sum` / `Sync` / `Monitor` — намеренно совпадают с
именами команд DSL, чтобы слово в интерфейсе и в скрипте было одним и тем же.
Обоснование и источники стандартных терминов Archicad — в `glossary.md`.

## Ограничение

Русские сообщения из C++ (`parseErrorText`, `sourceName` из моста) в EN-файле
не переводятся: они приходят из аддона. Расширение моста — отдельная задача.
